# v1.6.0 实施规格：首页 / 日历 / 设置 三页 UI 升级

> 本轮是**纯 UI 与功能组织**的一轮，不改协议、不改存储格式、不改任何后端接口。
> 施工依据：本文档。基线：v1.5.0（提交 `f02ef24`）。
> 构建命令：`bash tools/build.sh build`（必须 0 错误 0 警告）。

---

## 0. 全局硬约束（沿用 v1.5.0，一条都不能破）

1. **LVGL 回调里禁止阻塞**：回调都在适配器锁内，SD / flash / 网络 / 阻塞等待一律不行。
2. **内部 RAM 是最紧的资源**：批量数据 `MALLOC_CAP_SPIRAM`；不要新增大块静态数组。
3. **颜色/字号/间距一律取 `ui_theme.h` 的宏**，不写死字面量。
4. **触摸目标 ≥ 44×44**（`UI_TOUCH_MIN`）。
5. **先比较再写**（铁律二）：所有文本/颜色/进度条写入前先比较，值没变就不动。
   本轮三个页面都有 1 Hz tick，不做脏检查就会每秒重排一次整页。
6. **中文文案**风格与现有页面一致；不写英文占位。
7. **不新增组件、不引入新依赖**（`ui_pages` 现有依赖已含 `ai_service` / `word_service` /
   `calendar_service` / `todo_manager`；**不要**为了一个按钮去加 `idle_face` 依赖）。
8. **只改自己负责的文件**；不改 `version.txt` / `CHANGELOG.md` / `README.md` / `docs/API.md`
   （主调度统一收口）。
9. 风格与所在文件一致：中文注释，注释解释「为什么」。

### 0.1 面板高度预算（800×480，状态栏 40，页内边距 14×2 → 可用 412 px）

页面内容容器是**可滚动**的（`ui_core.c` 给每个页面容器加了 `LV_OBJ_FLAG_SCROLLABLE`），
所以超一点不会裁掉内容——但**目标是首页在一屏内放得下**，超出就要重新分配预算。

## 1. 日历页布局优化（`components/ui_pages/src/page_calendar.c`）

### 1.1 修掉时钟标签被裁的 bug（真缺陷）

- **现状**：`CAL_CLOCK_HEIGHT` = 24 px 的标签里塞**两行**文字
  （`"%02d:%02d:%02d\n%04d-%02d-%02d 星期%s"`）。20 px 字体两行约 52 px，
  24 px 的固定高度**必然把第二行裁掉**。
- **要求**：头部改成**一行三段**（flex row，不用固定高度裁切）：
  - 左：**大时间** `HH:MM`（`UI_FONT_HUGE`，48 px；未校时显示「--:--」），
    第二行小字 `2026-10-20`（`UI_FONT_SMALL`，muted）；
  - 中：**星期 + 本月待办数**（小字，如「星期一 · 本月 12 项到期」）；
  - 右：**「回到今天」「校时」两个按钮**（并入头部，见 1.2）。
  未校时时大时间显示 `--:--`，第二行显示「时间未同步」，并**不**高亮今天。

### 1.2 底部行动条并入头部

- 「回到今天」「NTP 校时」两个按钮从底部那 44 px 的行动条**移到头部右侧**，
  变成 2 个小按钮（高度 `UI_TOUCH_MIN`，宽度按文字自适应，`LV_FLEX_FLOW_ROW` + `pad_column`）。
- 原来的底部行动条整条去掉 → **底部腾出的 44 px 给网格**。
- 「NTP 校时」保持异步（`calendar_sync_ntp_async()`），不要改回同步调用。

### 1.3 网格

- 保留现有的 7 列网格、星期表头、日期按钮、到期圆点、今日/选中高亮逻辑，**不要重写**。
- 网格行高会因为底部腾出空间而变大（约 30 → 36 px），日期数字可以用 `UI_FONT_BODY`（20 px），
  圆点仍 6 px。
- 星期表头保持 `UI_FONT_SMALL`；周末列保持警示色。

### 1.4 选中日详情区扩容

- 现状：选中日面板只有 44 px 高，与底部行动条**互换位置**。
- 要求：现在底部没有行动条了，选中日面板可以**常驻在网格下方**，
  高度从 44 px 增到 **96 px**（`LV_SIZE_CONTENT` 更好，但要给个上限）。
  - 标题一行：`10 月 21 日 · 星期三 · 共 N 项`（`UI_FONT_SMALL`，primary 色）。
  - 下面列出当天待办（**纵向**列表，最多 3 条，多的用「还有 N 条」收尾），
    每条 `· 标题`（未完成）/ `✓ 标题`（已完成，muted 色）。
  - 没有待办时显示「这一天没有到期待办」。
- 未选中任何日期时，这个区域显示一行提示「点日期看当天待办」（muted，小字）。

### 1.5 其它

- 月份标题保持「2026 年 10 月」+ 上月/下月按钮。
- 月份切换、今天、点选同一天取消选择的交互**保持不变**。
- 网格数据来自 `todo_list()`，事件绑定保持不变。

## 2. 首页：三张等宽状态卡（`components/ui_pages/src/page_home.c`）

### 2.1 目标布局

```
抬头：问候 + 时钟 + 一行摘要（待办 N · 待同步 M · 存储）
今日待办（大卡，已有的，别动它的逻辑）
┌──────────┬──────────┬──────────┐
│ AI 对话   │  单词     │  日历     │   ← 本轮新增，三张等宽状态卡并排
└──────────┴──────────┴──────────┘
磁贴：WiFi · 待办 · 天气 · 设置（四个，一行排开）
```

- 三张卡**同一行、同一高度**（各 `LV_PCT(32)`，间距 `UI_PAGE_GAP`），
  视觉上是**同一级别**（这就是本轮「AI / 单词 / 日历同一级别」的意思）。
- 磁贴网格里**去掉「单词」和「日历」两个磁贴**（卡片已经是它们的入口，不要两个入口）。
  剩下 WiFi / 待办 / 天气 / 设置四个磁贴，各 `LV_PCT(23)`，一行排开。

### 2.2 三张卡各自显示什么（数据全部来自现有 API，不许新写后端）

**AI 对话卡**
- 标题：`AI 对话`
- 状态行：`ai_service_has_api_key()` 为假 → 「未配置 API Key」+ **警示色**，
  并补一行小字「请在网页端设置页配置」；
  为真 → 「已就绪」+ **成功色**，下一行显示 `ai_service_get_model()`。
- 再一行小字（muted）：当前对话轮数 `ai_service_history_count()`。
- 整个卡片可点 → `ui_nav_push(UI_PAGE_AI_CHAT)`。

**单词卡**
- 标题：`单词`
- 主行：`word_get_book()`（例如 `cet6`）+ 本地/云端标记
  （`word_cloud_mode()` 为真显示「云端」，否则「本地」）。
- 第二行：今日进度。优先用 `word_stats()` 的 `due`（今天该复习的条数）与
  `word_get_daily_count()`（每日目标），显示成「今日 3 / 10」。
  拿不到就显示「已学 N」(`word_stats().learned`)。
- 整个卡片可点 → `ui_nav_push(UI_PAGE_WORD)`。

**日历卡**
- 标题：`日历`
- 主行：今天的日期 + 星期（本地时区；用 `sys_time_synced()` 判断，未校时显示「时间未同步」）。
- 第二行：**今天到期的待办条数**（用 `todo_list_filtered(TODO_FILTER_DUE_TODAY, ...)`，
  见 `todo_manager.h`；取 count 即可），显示成「今天 2 项到期」；没有则「今天没有到期」。
- 整个卡片可点 → `ui_nav_push(UI_PAGE_CALENDAR)`。

### 2.3 脏检查（本页 1 Hz tick，不做就会每秒重排整页）

- 每张卡记住上次写入的**内容字符串**与上次用的**数据版本**；
  内容没变就一个字都不写（可复用文件里已有的 `label_set_text_cached()` 之类写法）。
- 单词卡用 `word_stats()`，每次调用都会遍历清单 —— 所以要**先比版本再取数**：
  用 `todo_version()`（待办相关）与 `word` 侧能拿到的计数（`word_stats` 本身较便宜，
  但仍要避免在内容没变时重写控件）。
- 日历卡的「今天」会随日期变化，跨天要重画。

### 2.4 不动的东西

- 「今日待办」大卡（`today_card_create`）的逻辑、脏检查、进度条**全部保留**。
- 抬头的问候语/时钟/摘要保留。

## 3. 设置页：补选项 + 改 UI（`components/ui_pages/src/page_settings.c`）

### 3.1 新增「AI 对话」卡片（放在「显示与待机」之后、「时间与时区」之前）

- **API Key 状态**：`ai_service_has_api_key()` → 「已配置」/「未配置」。
  **Key 本身永不显示**（与设备的其它密钥同规则）。
  未配置时给一行提示：「本机没有键盘，请在**网页端**配置」。
- **模型选择**：两个按钮 `deepseek-chat` / `deepseek-reasoner`，
  当前模型那个高亮（primary 色底）；点击即 `ai_service_set_model()`。
  未知模型名时两个都不高亮，并显示当前模型名。
- **保留轮数**：`ai_service_get_history_rounds()`，两个按钮 `−` / `+`
  （范围 1~10，步长 1），中间显示当前值。
- **系统提示词**：只读显示 `ai_service_get_system_prompt()` 的一句摘要
  （太长就截断），并注明「可在网页端修改」。
  ⚠️ **这个 getter 目前不存在**（只有 setter）——允许你顺手加上：
  在 `components/ai_service/include/ai_service.h` 声明
  `const char *ai_service_get_system_prompt(void);`，
  在 `components/ai_service/src/ai_service.c` 实现它（返回内部那份提示词即可）。
  本轮**只有你**碰 `ai_service`，不会和别人冲突。
- **清空对话**：`ai_service_clear_history()`，危险色按钮。

### 3.2 强化「单词」卡片

保留现有的「每日 −5 / +5 / 清空进度」，补上：

- **当前词书**（只读一行）：`word_get_book()`。
- **云端词库开关**：一个按钮在「云端词库：开 / 关」之间切换
  （`word_cloud_mode()` / `word_set_cloud_mode()`），切换后要 `word_cloud_refresh()`。
  切换前给一次确认（`ui_dialog_confirm`，见 `ui_core.h`）。
- **学习概览**（一行小字，muted）：已学 / 模糊 / 未记住
  （`word_stats()` 的 `learned` / `known_total` / `unknown_total`）。

### 3.3 「时间与时区」卡片

- 增加一行只读状态：当前时区（`calendar_get_timezone()` 或已有取法）与校时状态
  （`calendar_time_synced()`）→ 「CST-8 · 已同步」/「CST-8 · 未同步」。

### 3.4 「设备信息」卡片改成紧凑的键值网格

- 现在是一整块文本（`s_info_label`，小字换行）。改成**两列键值网格**：
  左边键（muted，小字），右边值（正文色，小字），逐行对齐。
- 行数控制在 8 行以内；超长的值（URL）单独占一行。

### 3.5 UI 统一

- 卡片标题目前用 `UI_FONT_TITLE`（20 px）。统一改成 **`UI_FONT_BODY`**（16 px）+ primary 色，
  让六张卡的标题看起来是同一套（腾出的视觉空间也留给内容）。
- 卡片间距统一用 `UI_PAGE_GAP`。
- 按钮沿用现有的 `add_button()` / `add_row()` 助手，**不要另起一套样式**。
- 页面内容变长后，**确认设置页容器可滚动**（`ui_core` 已给页面容器加了
  `LV_OBJ_FLAG_SCROLLABLE`）；如果设置页的父容器没有滚动，检查 `settings_create`
  是不是把内容直接塞进了 `parent`（是的话给 `parent` 加滚动或包一层可滚动容器）。

   - `components/ui_pages/src/page_calendar.c`（日历）
   - `components/ui_pages/src/page_home.c`（首页）

   `CHANGELOG.md` / `README.md` / `version.txt`（1.6.0）由主调度统一收口。

### 4.2 下一轮候选（本轮实测带出来的）

1. **`th_word_cq` 的 6 KB 内部栈**：联网时它就是内部 RAM 的一笔固定开销。
   可以考虑：栈缩到 4096（TLS 握手放不放得下要实测）、或者把云端队列的解析整体挪到 PSRAM。
2. **云端词队列的内部缓冲**：`words/maimemo.json` 解析时的中间缓冲同样在内部 RAM。
3. 设备端「快速添加」待办（没有 IME 时的折中方案）。
4. 待办数据模型升版（标签 / 子任务 / 重复规则 / 自定义排序）。

## 5. 本轮明确不做

- 不改任何 HTTP 协议、存储格式、NVS 键语义。
- 不做待办的数据模型升版（标签/子任务/重复）——那是 v1.7.0 的候选。
- 不做设备端「快速添加」待办（另开一轮）。
- 不给设置页加「立即进入待机」按钮（要加 `idle_face` 依赖，收益不抵依赖成本）。
- 不做页面的横屏/竖屏适配（本板固定 800×480 横向）。

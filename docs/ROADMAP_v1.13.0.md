# ROADMAP v1.13.0 —— 上位机的设备控制台（串口交互 + 预置指令）

> 需求：在上位机（浏览器页面）里做一个**串口交互**的功能，并**预设好一些指令**。
>
> 设备端本来就有一个调试 shell（`/api/v1/debug/exec`），
> 几十条命令：看内存、切页面、点控件、量重绘、重启……
> 但它只能用 `curl` 敲 —— 于是「人在设备旁边、屏幕亮着、手边只有浏览器」这种
> 最常见的调试场景，反倒最不方便。

## 1. 形状：一个终端 + 一排预置按钮

网页端新增一张卡片「设备控制台」：

* **输出区**：等宽字体、深色、固定高度、自动滚到底；最多留 400 行
  （再多就把最老的丢掉，别让页面越用越卡）。
* **输入行**：`Enter` 执行，`↑`/`↓` 翻历史（最近 50 条）。
* **预置指令**：按用途分成五组，每组一个标题，每个按钮一句话说明
  （鼠标悬停能看到说明和对应的命令原文）。

## 2. 走哪条路：HTTP，不是物理串口

「串口交互」这句话有两种做法：

1. **真的插线**：浏览器用 Web Serial API 打开设备的 USB 串口，
   直接和 UART0 上的控制台对话。
2. **走网络**：网页把命令发给设备的 `/api/v1/debug/exec`，
   设备和串口上跑的是**同一套 shell**。

选了 2，理由有三个：

* **设备端的 shell 本来就只在 HTTP 上**。串口上跑的是日志，
  命令要走 HTTP；做 1 还得先给设备加一条「从 UART 读命令」的路，
  而 UART0 的 RX FIFO 和 IDF 的控制台输出共用，动了它有风险。
* **Web Serial 只有 Chromium 系浏览器有**，Firefox/Safari 直接没有这个 API。
* **HTTP 这条路已经能用了**：shell 的命令、鉴权、LVGL 任务的 marshal
  都是现成的，做 1 反而要重做一遍「命令 → 输出」的那一套。

## 3. 预置了哪些指令

| 组 | 按钮 | 命令 | 为什么放进来 |
|---|---|---|---|
| 看一眼设备 | 版本 / 内存 / 任务 / 接口 / 存储 / 时间 | `version` `heap` `tasks` `routes` `storage` `time` | 出问题时第一个要看的六个 |
| 看一眼界面 | 当前页 / 界面结构 / 控件树 / 字形缓存 / 全部命令 | `pages` `ui` `widgets` `ftstats` `help` | UI 的 bug 都在这儿看 |
| 量一量 | 整屏重绘 / 冷字耗时 | `bench-screen 3`、`bench label 秦时明月 0 1` | 「卡」要变成数字才谈得上修 |
| 动一动 | 回首页 / 亮度 60 / 退出待机 / 说一句话 / 麦克风自检 | `page home` `bright 60` `idle exit` `speak 你好` `audio 1000` | 只读或可逆的，可以随便点 |
| 危险的 | 重启设备 | `reboot` | **要点两次**才执行（见下） |

挑它们的规矩：**只读或者可逆的随便点，会让设备消失的要确认**。

## 4. 一个实测才发现的坑：原生确认框靠不住

「重启设备」这种按钮，第一版用 `window.confirm()` 拦一下。
**实测在嵌入式浏览器里它被自动接受了** —— 点一下，设备真的就重启了，
连确认框都没看见。

原生对话框在嵌入式浏览器里可能被自动接受、也可能被吞掉，
两种都不该拿它当唯一的防线。

→ 改成**按钮自己上膛**：第一次点变成「再点一次确认」（变红），
五秒内再点才真执行；超时自动取消，点别的按钮也取消。
不依赖任何浏览器对话框。

## 5. 这一版做了什么

* `components/sync_server/web/index.html`：
  * 新卡片「设备控制台」（输出区 + 输入行 + 预置按钮）；
  * 预置指令用数据（`SHELL_PRESETS`）描述 —— 加一条指令就是加一个数组项；
  * 终端输出**一律当纯文本**（`textContent`），设备说什么都不会被当成 HTML；
  * 危险指令两次点击确认。
* 设备端**没有改动**：shell 早就有，这次只是给它一个用起来顺手的界面。
* 版本号 1.13.0。

## 6. 真机验证

浏览器里逐条点过：

* 卡片展开 → 五个分组、19 个按钮都在；
* 点「内存」→ 终端里出现 `$ heap` 和设备的真实输出；
* 输入 `version` 回车 → 同样的效果；
* `↑`/`↓` 翻历史（`version` → `heap` → 回到 `version`）；
* 「清屏」清空输出；
* 「重启设备」点一次 → 按钮变成「再点一次确认」，**终端里没有任何命令**；
  等 6 秒 → 自动变回「重启设备」；再点两次 → 终端出现 `$ reboot`，设备真的重启了。

## 7. 还没做的

* **真串口（Web Serial）**：设备端加一条「从 UART0 读命令」的路，
  浏览器用 Web Serial 直连。好处是 HTTP 挂了也能操作设备
  （这个项目有过「ping 通、串口正常，但任何 TCP 都建不上」的时候）；
  代价是 UART0 的 RX FIFO 和 IDF 控制台输出共用，要小心。
* **命令补全**：输入 `bench` 时提示可用的参数。
* **把控制台输出接到设备的日志上**：现在只有命令的输出在终端里，
  设备运行时的日志看不到（那些在串口上）。

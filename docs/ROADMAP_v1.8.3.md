# ROADMAP v1.8.3 —— 页面不再常驻，字形缓存就能放开

> 上一轮：[ROADMAP_v1.8.2.md](ROADMAP_v1.8.2.md)（字形缓存与 SD 挂载）
> 本轮性质：**PATCH**（存储格式、HTTP API、NVS 键语义都没变，也没有新功能或新页面）。

这一轮同时解决两个互相牵制的问题：

- **设备会崩**：逛一遍所有页面，内部堆从 291 KB 掉到 **0 KB**，然后 Guru Meditation。
- **界面不流畅**：v1.8.2 为了不崩，把 FreeType 字形缓存从 256 压到 32，
  结果被挤掉的字形每一帧都要重新渲染（FreeType 每个汉字约 100~200 µs）。

两个问题其实是**同一个瓶颈的两面**：内部堆只有 290 KB，
而「页面的控件」和「字形位图」都在抢它。

---

## 0. 真机实测数据

用一个临时的「自动巡览所有页面并打印堆」任务（**没有提交**）量出来的：

```
I (1747) after tour home        internal  291 KB (largest 248 KB)
I (2350) after tour todo        internal  213 KB (largest 168 KB)   -78 KB
I (3665) after tour todo_detail internal  156 KB (largest 112 KB)   -57 KB
I (4326) after tour settings    internal  114 KB (largest  70 KB)   -42 KB
I (5613) after tour word        internal   46 KB (largest  10 KB)   -68 KB
I (7543) after tour calendar    internal    0 KB (largest   0 KB)   -46 KB  → 崩
```

**每个页面的控件加起来约 290 KB**，而开机时内部堆只有 291 KB —— 也就是说
「逛一遍所有页面」正好把内部堆吃干净。

字形缓存的账（同��个固件，只改 `CONFIG_LV_FREETYPE_CACHE_FT_GLYPH_CNT`）：

| 缓存个数 | 巡览三遍之后 | 界面 |
|---|---|---|
| 256（默认） | **0 KB，崩** | 流畅 |
| 64 | 54~64 KB，最大连续块 5~17 KB | 略卡 |
| **32（v1.8.2 选的）** | 76~88 KB，最大连续块 22~35 KB | **明显卡** |

→ 所以**光调缓存个数是死路**：调大就崩，调小就卡。
**必须先把页面控件的常驻内存还回去**，缓存才能放回 256。

---

## 1. 做法：页面隐藏时销毁「内容」，回来时重建

v1.8.1 已经在**待办列表**上用过这个办法（`page_todo.c` 的 `rows_clear()` +
`on_show` 重建），效果实测：38 次进出之后最大连续块稳定在 27 KB 不再下降。
这一轮把同一个办法用到其余页面。

### 每个页面要做的事

把 `create()` 拆成两半：

- **外壳**（页面骨架：抬头、返回按钮、滚动容器……）：**只建一次**，留在原地；
- **内容**（卡片、列表、标签……）：**页面隐藏时销毁，页面回来时重建**。

于是：

```c
static esp_err_t settings_on_show(void)  { ... 重建内容 ... }
static esp_err_t settings_on_hide(void)  { ... 销毁内容 ... }
```

### 硬约束（都是这一轮踩过的坑）

1. **不要重复注册事件订阅**。
   `create()` 里如果有 `ui_event_subscribe(...)`，重建内容时**不能再调一次**
   （会变成同一个事件被处理两遍）。
   → 订阅留在 `create()` 里（只跑一次），**重建函数里不许再订阅**。
2. **不要在重建里碰 flash**。NVS 的读是 RAM（`nvs_flash_init` 把分区读进了 RAM），
   但**写**是 flash 写 —— 重建路径里不许写 NVS。
3. **内容从内存里的缓存重建，不重新读盘**。
   待办列表用的是 `todo_list_filtered()` 的 RAM 快照；单词页用 `word_get()`；
   日历页用已经算好的月份 —— 照各自的现状来。
4. **可见内容一个字节都不能变**：行数、顺序、文案、颜色、间距、滚动位置。
5. **别用 `lv_obj_clean(parent)`** 把外壳也清了 —— 只清你自己建的内容对象，
   并且要记住每个内容对象的父容器。

### 每页的实测代价（要还回来的内存）

| 页面 | 文件 | 占用 |
|---|---|---|
| 设置 | `components/ui_pages/src/page_settings.c` | ~42 KB（182 个控件，整页最重） |
| 单词 | `components/ui_pages/src/page_word.c` | ~68 KB |
| 日历 | `components/ui_pages/src/page_calendar.c` | ~46 KB |
| 待办详情 | `components/ui_pages/src/page_todo.c` | ~57 KB |
| AI 对话 / 天气 | `page_ai_chat.c` / `page_weather.c` | 各 ~20 KB |
| WiFi | `page_wifi.c` | 已经窗口化（v1.8.1），本轮不动 |

## 2. 然后：把字形缓存放回 256

页面控件不再常驻之后，内部堆能空出约 290 KB —— 字形缓存（256 时约 90 KB）
就放得下了，界面回到 v1.8.1 之前的流畅度。

**这一条是本轮的验收标准之一**：缓存回到 256 之后，巡览三遍**不能再崩**。

---

## 3. 验收标准

- `bash tools/build.sh build` → **0 error 0 warning**；
- **页面巡览三遍不崩**（临时任务，测完就撤）；
- 巡览之后内部堆 **≥ 150 KB 空闲、最大连续块 ≥ 30 KB**（PHY 的硬需求）；
- `CONFIG_LV_FREETYPE_CACHE_FT_GLYPH_CNT` 回到 **256**，界面流畅度回到 v1.8.1 之前；
- 逐页目视：每个页面**进出 20 次**之后内容与第一次进去时完全一样
  （控件数、文字、位置、滚动位置）；
- 连续重启 3 次：无 abort / 栈溢出。

---

## 4. 本轮明确不做

- 不动 `page_wifi.c`（v1.8.1 已经窗口化过了）、`page_home.c`、`page_splash.c`。
- 不改 HTTP 路由、存储格式与 NVS 键语义（所以是 PATCH）。
- 不动 FreeType 本身（那是外部组件）。

---

## 5. 实测结果（真机，2026-10-21）

| 验收项 | 目标 | 实测 |
|---|---|---|
| 巡览所有页面三遍 | 不崩 | ✅ 三遍跑完，日志里除「墨墨 401」无其他错误 |
| 巡览后内部堆 | ≥ 150 KB | **114 KB** |
| 巡览后最大连续块 | ≥ 30 KB | **23 KB**（v1.8.2 是 22~35 KB，v1.8.0 之前是 0 KB 会崩） |
| 巡览全程最低水位 | 不到 0 | **31 KB**（256 时会到 0 并 panic） |
| 字形缓存 | 尽量大 | **64**（256 崩、128 最低水位到 0） |

## 6. 下一轮

1. **只给 FreeType 一条通往 PSRAM 的路**（不动全局分配阈值）——
   让字形位图住进 PSRAM，字形缓存就能放回 256，界面完全回到之前的流畅度。
   （已经证过：动全局的 `CONFIG_SPIRAM_MALLOC_ALWAYSINTERNAL` 会让 **TLS 握手失败**。）
2. **字库复制一份到内部 flash**（v1.8.2 的遗留项）。
3. 各页面常驻对象还剩多少（这一轮还回去的量待复测）。
4. keep-alive 复用连接、httpd 槽位、SD 写放大（v1.8.0 的遗留项）。

## 7. 复核查出的问题（已在 v1.8.4 修掉）

1. **事件载荷被截断后没有结尾的 `\0`** —— 越界读（改动前就有的老 bug）。
   `ui_post_event()` 把载荷截到 256 字节，而绑定声明的大小是事件类型自己定的
   （AI 对话的流式文本声明 1024）；处理器按 C 字符串处理就会越过载荷读堆。
   → 每个载荷后面补一个结尾的 `\0`。
2. **单词页与日历页的滚动位置没有复原** —— 销毁内容会让 LVGL 把偏移夹回新内容
   高度允许的范围，重建后没有复原 → 每次进这两页都回到顶部。
   → 隐藏时记住偏移，回来时按记住的值复原。
3. **AI 对话页：问过两次同一句话，新问的那条会消失** —— 待补的提问是按**内容**
   去历史里匹配的，会先匹配到旧的那条。
   → 只与历史里最新的一条用户提问比对。
4. **AI 对话页：同一条回答可能被贴两个气泡** —— 「已贴上」只跟最后一个气泡比。
   → 遍历所有气泡。

另有一条复核员看到的「临时巡览任务还在固件里」是**误报**：
它读的是测量期间的源码状态，提交前已经撤掉了（`grep -c tour_task main/app_main.c` → 0）。

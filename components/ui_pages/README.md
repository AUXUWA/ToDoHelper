# ui_pages

**L4 页面集合** — 按需求 §10.1 实现全部页面，并维护**页面表**。

- 头文件：`include/ui_pages.h`（只有 `ui_pages_init()`）
- 依赖：`ui_core`、`sys_utils`（后续按需增加各业务组件的**公开头文件**）
- 被谁依赖：`main`

### 启动页的刷新节流（v1.7.0，`ROADMAP_v1.7.0.md §1 A3`）

启动这 6.4 秒里**启动页是唯一可见的页面**，UI 任务的时间全花在这上面，所以：

| 项 | 以前 | 现在 | 为什么 |
|---|---|---|---|
| 日志刷新周期 `SPLASH_TICK_MS` | 100 ms（10 Hz，跑 64 次） | **250 ms（4 Hz，跑 ~26 次）** | 每次有新日志都 `lv_label_set_text_static()` 那个最多 5 KB 的标签 → 下一次布局要把整段文字重新量一遍。10 Hz → 4 Hz 直接把这笔开销砍到 2.5 分之一 |
| 状态行 | `lv_label_set_text_fmt()` | 静态缓冲 + `lv_label_set_text_static()` + **先比较再写** | `set_text*` 即使文字一模一样也会 invalidate 标签（AGENT.md §9.0.1.1 铁律 2）；而且 `set_text_fmt` 每次都要 malloc/free 一份副本 |

- **日志仍然是增量的**：环形缓冲里的新行是**追加**到渲染缓冲的（不是每次全量重建），
  这条没动，只是跑的次数少了。
- **追加遇到「已认领但还没发布」的行时整批回滚**：`sys_log` 的写入方先占序号、
  后发布内容（`sys_log.c` 的 `recent_capture()`），读者完全可能读到一条
  **已被认领但尚未发布**的行。这种情况下追加分支把**这一批整个撤掉**
  （文本与已用长度都还原），下一拍从同一起点重来 —— 否则那一批行会被追加两遍
  （屏幕上出现重复的启动日志），要等环形缓冲溢出触发一次全量重建才会消失。
- **「最新一条」状态行按同一节流走**（同一个 250 ms 定时器），文案格式一字未改：
  `启动日志 N 条 · 最新 S.Ts · 启动中...`。
- 省略号的节奏（420 ms 一点）由**墙上时钟**算相位，不是数 tick，所以把 tick 放宽到
  250 ms 之后点还是会照常一个一个长出来（tick 比点的周期短，相位每次最多 +1，不会跳点）。
- 观感不变：字体、颜色、滚动到最新行、启动进度提示都保持原样。

## 三个主页面的布局（v1.6.0 重排）

> 布局数字都是**真机实测**的（用板载调试 shell 的 `widgets` 打印控件树，坐标与尺寸都在里面），
> 不是估算。可用高度 = 480 − 状态栏 40 − 页内边距 14×2 = **412 px**（页面容器 435 px，可滚动）。

### 首页（`page_home.c`）：仪表盘

```
抬头（62 px）   问候 + 一行 [时钟 · 摘要]
今日待办（89…127 px）  大卡：计数 + 进度条 + 最多 2 条标题 + 说明行
三张状态卡（111 px）   AI 对话 · 单词 · 日历 —— 同一行、同一高度、同一套视觉
磁贴（118 px）  WiFi · 待办 · 天气 · 设置
```

- **三张状态卡是「同一级别」**：结构完全相同（标题 + 主行 + 一行小字），
  高度天然一致；点整张卡进对应页面（`ui_nav_push`）。
- 每张卡的数据来源：`ai_service_has_api_key()` / `ai_service_get_model()`、
  `word_get_book()` / `word_cloud_mode()` / `word_stats()`、
  `todo_list_filtered(TODO_FILTER_DUE_TODAY, ...)`。
- **取数是节流的**：首页 1 Hz tick，但 AI 卡每 5 个 tick 才读一次 NVS，
  单词卡用「便宜指纹」比对（词书/云端/词数/每日目标/时间桶），
  日历卡用 `todo_version()` + 日期 + 校时状态比对 —— 指纹没变就一个字都不写。
- 磁贴从 6 个减到 4 个：**单词与日历已经有卡片当入口了**，不再给两个磁贴（一个入口只留一处）。

### 日历页（`page_calendar.c`）：头部一行三段

```
头部（58 px）   返回 | 大时间 14:09（48 px） | 日历 · 10 月 20 日 星期二 / 本月 N 项到期 | 回到今天 · 校时
月份行（44 px） 上月 | 2026 年 10 月 | 下月
网格（… px）    星期表头 + 7 列日期按钮（105×40，圆点是当天有到期）
详情区（25 px） 选中日：日期 · 星期 · 共 N 项 + 当天待办（最多 3 条）；未选时提示「点日期看当天待办」
```

- 头部不再有「24 px 高的标签塞两行文字」那种写法（那会把第二行裁掉）；
  每个标签的高度都是内容自适应。
- 网格的**行轨道按这个月的周行数重算**（`cal_grid_rows()`）：LVGL 的 FR 轨道会把剩余高度
  平均分给**所有** FR 行，空着的那一行也照样吃一份 —— 固定 6 行时 5 行的月份白丢 1/6，
  日期格子只有 30 px 高。重算后是 40 px。
- 原来的底部行动条（「回到今天 / NTP 校时」）并进了头部，省下的 44 px 给网格。

### 设置页（`page_settings.c`）：六张卡

`显示与待机` → **`AI 对话`** → `时间与时区` → `单词` → `局域网与安全` → `设备信息`。

- 新增「AI 对话」卡：Key 状态（**永不显示 Key 本身**）、模型选择、保留轮数 ±、
  系统提示词摘要（只读）、清空对话。
- 「单词」卡补了：当前词书、云端词库开关（切换前确认）、学习概览。
- 「设备信息」从一整块文本改成**两列键值网格**（长值单独占一行）。
- 六张卡的标题统一 `UI_FONT_BODY` + primary 色，间距统一 `UI_PAGE_GAP`。
- 页面变长了，靠 `ui_core` 给页面容器加的 `LV_OBJ_FLAG_SCROLLABLE` 滚动。

## 待办页：设备端可「勾选完成 + 删除」，新增/编辑只在网页端

设备端待办 UI（`src/page_todo.c`，列表页 + 只读详情页）保留**两个**写操作：
**行首勾选框切换完成状态**（`row_toggle_cb` → `todo_set_done()`，**失败会回滚勾选状态**，
不让 UI 撒谎）与**行尾 52×34「删除」按钮**（`todo_delete()`）。
**新增与编辑只由电脑网页端完成** —— 本板无中文 IME，软键盘输入中文不现实。

- 列表页提示语：`TODO_READONLY_HINT = "此页可勾选完成 / 删除 | 新增请到电脑网页端"`；
- 已移除的入口：列表页底部「新增」按钮及其文字输入浮层 + `ui_keyboard_create()` 软键盘、
  批量按钮「标记已同步」/「清除已完成」、详情页底部的「完成/取消 / 优先级 / 删除」条
  （详情页因此是**只读**的：标题、备注、状态、优先级、到期、同步状态）；
- 保留的查看能力：列表的完成指示 + `✓` 前缀 + 颜色、同步状态徽标、统计行
  「共 N 项 · 已完成 N · 待同步 N」，点击整行进详情页；两页都
  `ui_event_bind(TODO_EVENT, TODO_EVENT_LIST_CHANGED, ...)`，网页端改动后自动重绘。

为什么这样定：

1. 800×480 触摸屏 + 软键盘的中文输入体验很差，实际可用性远不如网页；
2. **单一新增/编辑入口**：新增与编辑只走网页，避免两端同时改写同一项导致互相覆盖；
3. 勾选与删除留在设备上是**用户明确要求**的（"在设备上看到就想直接划掉"），
   而且这两个操作不需要输入；失败时回滚状态，保证设备端显示与 NVS/卡上的数据一致。

> 历史：曾经整页做成"完全只读"（连勾选和删除都移除），用户实测后澄清要保留这两个操作，
> 于是按上述语义收敛。详见 `docs/HANDOVER.md §0.5.2` 与 §3 需求 4。

## 新增一个页面（扩展点）

1. 建 `src/page_xxx.c`，导出 `const ui_page_t page_xxx = { .id = UI_PAGE_XXX, ... };`
2. 在 `src/pages_internal.h` 加 `extern const ui_page_t page_xxx;`
3. 在 `src/ui_pages.c` 的 `s_pages[]` 加一行；
4. 在 `CMakeLists.txt` 的 `SRCS` 加文件；
5. 若需要新的页面 id，在 `ui_core.h` 的 `ui_page_id_t` 加枚举
   （**顺序必须与需求 §10.1 对应表一致**）。

## 页面实现规范

- 只用 `ui_theme.h` 的配色/字号/间距，不写字面值与绝对坐标（需求 §10.3）；
- 触摸控件高度 ≥ `UI_TOUCH_MIN`（44 px）；
- 布局用 flex（`LV_FLEX_FLOW_COLUMN` / `ROW_WRAP`），不要 `lv_obj_set_pos()`；
- 只通过 `create(parent)` 传入的容器建控件，不要碰屏幕或其他页面；
- 需要业务数据时**订阅事件**（`ui_event_bind`）或读 `sys_status_get()`，
  不要直接调用 service 的阻塞接口；
- 时间相关 UI 必须先判断 `sys_time_synced()`，未同步时显示 `UI_STATUS_TIME_UNSYNCED`。

## 测试方法

```powershell
idf.py build && idf.py -p COM34 flash monitor
```

逐页点开：每页都应显示自己的标题、左侧"返回"按钮，且顶部状态栏保持不动。

对待办页额外确认（1.0.0 语义）：列表页底部应看到提示文字
**「此页可勾选完成 / 删除 | 新增请到电脑网页端」**，行尾有 52×34「删除」按钮；
点行首勾选框应切换完成状态（**失败会回滚**，可故意拔卡验证），点整行进只读详情页；
**不应出现**新增按钮 / 软键盘 / 批量按钮。在电脑网页端改一条待办，设备端应在不触摸屏幕的
情况下自动刷新（`TODO_EVENT_LIST_CHANGED`）。
